## Commands

```bash
npm run dev          # Dev server at http://localhost:1313 (live reload)
npm run build        # Production build → public/
npm run preview      # Production build with minify, watch mode
npm run format       # Run Prettier across all files
```

For development on a remote server:
```bash
hugo server --bind 0.0.0.0 --baseURL http://<HOST_IP> --theme hugoplate
```

To update Hugo modules (Go-based theme dependencies):
```bash
npm run update-modules
```

## Architecture

This is a Hugo static site using the **Hugoplate** theme (`themes/hugoplate/`). The site is deployed to Vercel (primary), with Amplify and Netlify also configured.

### Configuration split
- `hugo.toml` — core Hugo settings (baseURL, theme, build pipeline, plugins list, markup config)
- `config/_default/params.toml` — site parameters (logo, search, SEO metadata, Google Ads/Analytics IDs)
- `config/_default/menus.en.toml` — navigation menus
- `config/_default/languages.toml` — language settings (only English is active)
- `config/_default/module.toml` — Hugo module mounts

### Content structure
All content lives under `content/english/` (the multilingual path, even though only English is active). Key sections:
- `blog/YYYY/MM/<slug>/` — each post is a directory with `index.md` + `featured_image.webp`
- `books/`, `projects/`, `events/`, `about/`, `contact/`, `authors/`

### Blog post frontmatter
New posts use YAML frontmatter. Required fields:
```yaml
---
title: ""
meta_title: ""        # Used for <title> tag / OG title (keep ≤60 chars)
description: ""       # Meta description (120–160 chars)
date: YYYY-MM-DDT00:00:00Z
image: "featured_image.webp"
categories: [""]
author: "Steve Scargall"
tags: [""]
draft: false
aliases:
---
```

Older posts may use TOML frontmatter (`+++` delimiters) — both formats are valid.

### Theme customization
Avoid editing files inside `themes/hugoplate/` directly. Override by placing files at the same path under `layouts/`. Currently `layouts/partials/basic-seo.html` overrides the theme's SEO partial.

### CSS pipeline
Tailwind CSS is processed through PostCSS. Hugo reads `hugo_stats.json` to drive cache-busting — this file is auto-generated by `hugo --gc` and tracked in git. The Tailwind config is in `tailwind.config.js`.

### Hugo modules
Feature modules (search, accordion, SEO tools, gallery, cookie consent, etc.) are Go modules from `github.com/gethugothemes/hugo-modules`. They are referenced in `go.mod` and mounted via `config/_default/module.toml`. Run `npm run update-modules` to upgrade them.

### Static assets
- `static/` — served as-is (images, fonts, JS plugins like Swiper, GLightbox, Font Awesome)
- `assets/` — processed by Hugo pipes (CSS, JS that goes through PostCSS/Tailwind)
- `data/social.json` — social media links used in footer/author templates
- `data/theme.json` — color palette overrides for the theme
