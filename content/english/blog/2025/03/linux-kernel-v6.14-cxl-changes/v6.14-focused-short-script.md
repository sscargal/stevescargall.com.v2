## SCRIPT

**[0:00 — HOOK, on screen: `if (type == CXL_DVSEC_DEVTYPE_3)` in red]**

"Your CXL accelerator is plugged in. Kernel boots fine. But Linux is silently ignoring its memory map — because of a one-line type check."

**[0:08 — cut to: CXL type table: Type 1 / Type 2 / Type 3]**

"CXL defines three device types. Type 3 is a pure memory expander. Type 2 is an accelerator — think AI inference cards — that also has its own device-managed memory. Type 1 is accelerators like FPGAs with no local memory."

**[0:20 — cut to: function name `cxl_dvsec_rr_decode()` in pci.c]**

"`cxl_dvsec_rr_decode()` reads DVSEC Range Registers — the hardware table that tells the kernel where a CXL device's memory aperture lives. Without this, there's no region creation, no NUMA node, no `/dev/dax` entry."

**[0:32 — cut to: git diff, before block highlighted]**

"Before v6.14, this function only ran for Type 3. Type 1 and Type 2 devices hit this guard and returned early — their memory ranges were never registered."

```c
/* BEFORE */
if (type == CXL_DVSEC_DEVTYPE_3)
    return cxl_dvsec_decode_ranges(...);
```

**[0:44 — cut to: after block, new lines highlighted in green]**

"The fix: extend the check to cover all three types."

```c
/* AFTER — v6.14 */
if (type == CXL_DVSEC_DEVTYPE_1 ||
    type == CXL_DVSEC_DEVTYPE_2 ||
    type == CXL_DVSEC_DEVTYPE_3)
    return cxl_dvsec_decode_ranges(...);
```

**[0:55 — cut to: `cxl list -v` output showing memory ranges]**

"Small diff. Large impact. CXL accelerators and FPGA cards on kernels before 6.14 had silent enumeration failures. Now they don't."

**[1:05 — face cam or text card]**

"If you're testing CXL Type 2 hardware, 6.14 is your minimum kernel. Link to the commit in the description. Follow for a new CXL kernel deep dive every release."

**[1:12 — END]**

## RATIONALE FOR SELECTION

This feature was chosen over the other v6.14 explainers for the following reasons:

1. **Concrete, demonstrable bug**: Before this patch, Type 1 and Type 2 CXL device memory ranges were silently never registered. That is a correctness gap, not a style issue — and it is directly testable on real hardware.

2. **Tight code story**: The entire fix is a 3-line condition extension. That makes for an ideal YouTube Short: the diff fits on screen, the before/after is unambiguous, and there is no hand-waving required.

3. **High relevance right now**: CXL Type 2 devices (GPU-class accelerators with device-managed memory) are entering production. Engineers evaluating or shipping this hardware need to know the minimum kernel version for correct enumeration — v6.14.

4. **Universal audience hook**: The phrase "your accelerator is plugged in but the kernel is ignoring its memory" is viscerally relatable to any kernel or platform engineer, regardless of CXL expertise level.

The CXL 3.1 event record updates (explainer 02) cover four commits and are better suited to a longer format video. The Component Identifier (explainer 03) is important for RAS engineers but narrower. The device_match_type cleanup (explainer 04) and regblock refactor (explainer 05) are internal hygiene changes with no user-visible correctness impact — not the right material for a 90-second urgency-driven short.
